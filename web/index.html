The supervisor for coding agents

Undo what your coding agent did, shell commands included.

Provenrail is the supervisor for coding agents: one hook, on Claude Code, Codex, Gemini CLI, Copilot and Cursor. Before every action that can change a file it checkpoints the working tree into a store outside your repository. Claude Code's own documentation says its checkpointing "does not track files modified by Bash commands" (read 9 October 2026). This does.

pr undo last 
# A real Claude Code session, told to
# run rm -rf src in a directory
# holding uncommitted files.
> rm -rf src
# Its own reply:
  Deleted `src` (untracked, so not
  recoverable from git).

# Both files came back. Last line
# of the output:
$ pr undo last
  Verified: the working tree now
  matches the checkpoint exactly.

What undo does not cover: gitignored files, apart from root-level .env files; any file over 50 MiB, which is skipped and listed; git history, databases and anything outside the repository. It works inside git repositories only. Checkpoints are kept for 14 days. Nested repositories and submodules are recorded as a pointer and are never touched by a restore. If a snapshot cannot finish in 10 seconds, checkpoints pause for that project and Provenrail says so; the call still runs. Details and cost.

What it does

One hook, eight jobs.
Each one says what it cannot do.

What you get for running coding agents, in the order you are likely to need it.

Undo pr undo
A checkpoint of the working tree before every action that can change a file, kept in a shadow git store outside the repository. pr undo lists them with what each action changed, pr undo last restores, and a full restore is verified by tree hash. Inside Claude Code it is /guard-undo. LimitGitignored files are not covered apart from root-level .env files. Files over 50 MiB are skipped and listed. Git history, databases and anything outside the repository are not rewound. Git repositories only. Checkpoints are kept for 14 days. Nested repositories and submodules are recorded as a pointer and are never touched by a restore. If a snapshot cannot finish in 10 seconds, checkpoints pause for that project and Provenrail says so; the call still runs.
Stop pr stop
Refuses every tool call from every agent on the machine until pr resume. In the plugin it is /guard-stop. LimitIt reaches agents that run the Provenrail hook, at each one's next tool call. A call already running is not interrupted.
Loop breaker
Puts the next call to a human after the same call, or the same short cycle of one to three calls, has repeated 8 times back to back. The threshold is measured, not guessed: across 3,186 real Claude Code sessions and 147,356 tool calls on the author's machine, 97.1% of sessions never repeated a block at all and 0.47% would have been questioned. LimitIt asks rather than blocks, because polling a build is also a run of identical calls. Cycles longer than three calls are not looked for.
File lanes
When two agent sessions work in one checkout, the second is asked before it edits a file the first wrote in the last 15 minutes. LimitNot a lock. It sees edits made by file-editing tools, not by shell commands.
Phone remote pr remote setup
Approve or refuse a risky call, and stop or resume every agent, from Telegram (your own bot) or ntfy (a secret topic). How it works. LimitThe text of a question passes through the service you chose. It never fails open. On ntfy, anyone who knows the topic name can answer, and so can a program running in your own account; Telegram is the stronger channel. The remote guards against a trusted agent's mistakes while you are away, not against hostile software running as you.
Rules and spend cap
45 default rules that screen where a command points, not which verb it uses; a day spend cap; a subagent fan-out cap. Every rule. LimitA rule matches text, so a command written to defeat a pattern is not caught. The dollar figure is an estimate.
Scan pr scan
What in a repository you just cloned runs or steers an agent without asking: hooks, MCP servers, folder-open editor tasks, devcontainer and install scripts, hidden Unicode and HTML comments in instruction files. In the plugin it is /guard-scan. LimitIt screens known auto-run surfaces and does not judge the code. "Nothing found" is not "this repository is safe".
Brief pr brief
A review brief of what the agent changed, built from recorded checkpoints and the guard journal, not from the agent's own summary: net change, files touched and reverted, shell commands that changed files, sensitive paths (lockfiles, migrations, auth, CI, agent config), and what was stopped or questioned. LimitIt states facts and names what to check. It does not claim that tests pass.
Underneath: the signed record
Every decision can be signed into a hash-chained record that anyone can verify with an open-source tool, in your browser or on the command line. Verify a real one. LimitA process that never calls the hook will not appear in it.
Undo

Claude Code rewinds its own edits.
A shell command is where work is lost.

A working tree is lost through rm -rf, git checkout ., a formatter run over the wrong directory, a codemod, a script the agent wrote a minute ago. So the checkpoint is taken in the one place that sees all of them, the tool hook, and it is a snapshot of the whole tree rather than of the file the tool says it will touch.

The store is a separate git object store under ~/.provenrail. Your project's real .git is never opened or written, so there is nothing for git status to show. Measured on a 381-file repository: 1.04 s for the first snapshot, 0.03 s for each one after. The supervisor adds about 8 ms to a hook call that takes no snapshot (78 ms against 70 ms before, Python 3.9).

  • Gitignored files, apart from root-level .env files.
  • Files over 50 MiB, which are skipped and listed.
  • Git history, databases and anything outside the repository.
  • Anything outside a git repository: it works inside git repositories only.
  • Anything older than 14 days: checkpoints are kept for 14 days.
  • Nested repositories and submodules: recorded as a pointer, never touched by a restore.
  • A snapshot that cannot finish in 10 seconds: checkpoints pause for that project and Provenrail says so; the call still runs.

Before you change anything

One command tells you
how wide your own sessions spread.

A guard only pays out on a day that has not happened yet. The transcripts of the work your agents already did are sitting in ~/.claude/projects right now. pr report reads them, offline, and says what they cost, what they ran, what they touched, and which of their commands these rules would have stopped.

uv tool install provenrail && pr report

Nothing to set up, no account, no config file, and no network call. It is useful the first time you run it, which is the one thing no guard can be. Four flags: --since for a window, --project to narrow by name, --json for the versioned machine-readable document, and --share for the version that is safe to post, which drops the root path, replaces every project name with a short hash, and reduces each command to its verb and flags so nothing left in it is an operand.

The dollar figure is estimated at API list price, and notional on Pro and Max flat-rate plans, where there is no per-token charge at all. It is also a floor. Over the 49 sessions in the run below where Claude Code had recorded its own total, this estimate came out about 12 per cent under it. Two known causes are not modelled because neither is visible in a transcript: fast mode bills Claude Opus 5 at $10/$50 per million tokens against the standard $5/$25, and web search bills $10 per 1,000 searches. No multiplier is guessed at to close that gap, so the number misses low rather than high.

What auto mode already does, and does well

In an interactive session, Claude Code "runs git status itself before a command that would discard uncommitted work, such as git reset --hard or rm -rf", and it "never lets a permissions.allow rule or a PreToolUse hook that returns 'allow' approve an rm or rmdir command that targets a critical path". If an interactive session on Pro, Max or Team is the only place you run agents, you already have most of what a destructive-command guard sells, free, and did not have to install it.

What it is not is a cost control, and it is not present when the session did not start in auto mode. Those two gaps are what this product is for.

Limits, stated plainly

Anthropic's hooks documentation says the permissionDecision field on PreToolUse and PermissionRequest hooks "is ignored in bypassPermissions mode, when the classifier hasn't finished running (indicated by pendingClassifier: true), or when the API has denied the call". So under --dangerously-skip-permissions Provenrail journals the decision and tells the agent, and does not stop it. permissions.deny rules are a different mechanism and do block in every mode; a hook is not one of those, and we will not imply otherwise.

A rule matches text. A command written to defeat a pattern, a delete hidden inside a script or a one-liner, is not caught. That is a property of every hook of this kind, this one included. What target resolution buys is precision on the commands agents actually emit, not immunity to one written to get past it.

One command

A day cap the agent
cannot talk its way past.

Print mode has a per-run --max-budget-usd; nothing built in caps a day across runs and interactive sessions. Provenrail enforces a day cap before the next tool call.

The hook payload already carries transcript_path. Provenrail reads that transcript from where it last stopped, prices every new assistant message from its reported model and token usage, adds the delta to a ledger that survives across hook processes, and refuses the next tool call once the day is over budget.

pr guard budget 25

There is no default cap, because a cap you did not choose is a claim about your money. Set one and pr guard status prints what has been spent against it. Two things this page will never soften: the figure is estimated at API list price and is notional on Pro and Max flat-rate plans, where there is no per-token charge to cap; and the transcript is written asynchronously, so the cap stops the agent within a turn rather than at the exact dollar.

The policy

It screens where a command points,
not what it is called.

Nobody has ever lost work to the letters rm -rf. They lost it to what came after them. rm -rf .next comes back in twelve seconds. rm -rf ~/ is the end of a laptop. A pattern cannot tell those apart, because the difference is not in the text, it is in where the text points. So the rules resolve the target against the working directory the host hands them.

We measured that against one frozen corpus: 36,977 Bash commands pulled from 1,247 real agent sessions, replayed offline in the directory each one actually ran in. Verb matching interrupted 923 of them. Target resolution interrupts 222. On 40 commands taken from public data-loss reports, it stops 40 of 40. Run the same measurement over your own transcripts with python tools/measure_guard.py, which makes no network call.

Every rule, and what it does

Underneath: the signed record

A rule name is not evidence.

When a model-based classifier stops something, what survives is a line in a chat log and a label such as [Data Exfiltration]. Nothing a third party can recompute. Every Provenrail decision is Ed25519 signed and hash-chained to the one before it, so a client, an auditor or the other side of a dispute can check it without trusting the agent, the server, or us. Underneath: how a decision is recorded

Decide, record, check.

Three moving parts, because fewer parts to trust means less to audit.

01Decide

The verdict is computed locally

The hook reads the tool call, resolves its target against your working directory, prices the transcript against your cap, and answers. No network call is in that path, so an unreachable server can never turn a refusal into an allow.

02Record

Each decision links to the last

Allowed, refused or escalated to a human, every decision is signed and carries a hash of the one before it. Reorder or delete one and the chain stops matching. pr guard receipt exports the lot as a portable bundle.

03Check

Anyone can check it without you

The open-source verifier reconstructs the chain offline. A Python implementation and a browser one are held to frozen public conformance vectors in CI, so verification never depends on running our code. An RFC 3161 anchor adds a public authority's time.

Install

In the plugin the commands are /guard-undo, /guard-stop, /guard-scan, /guard-status, /guard-card and /guard-budget.

The CLI commands pr undo, pr stop, pr resume, pr remote setup, pr away, pr back, pr scan and pr brief need version 0.6.0. Install it from GitHub, because the package on PyPI is older and does not have them:

uv tool install git+https://github.com/pofky/provenrail

For headless and CI, pr guard install writes the same hooks into the project's .claude/settings.json, preserving any hooks already there. Anthropic's documentation states that "without --bare, a -p session runs the hooks in a project's .claude/settings.json", so that one file is the whole CI setup.
