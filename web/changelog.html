Changelog

What changed, and when

Notable releases of the Provenrail SDK, the open-source verifier, and the platform. The Python package is on PyPI and the recording SDK is on npm.

0.2.18August 5, 2026Verification
  • The two verifiers no longer disagree about a broken file. A structurally invalid bundle (a list-valued key set to a string, a missing stream_id, a seq that is not a number) made the CLI report TAMPERING DETECTED while the browser threw and showed a neutral "could not verify". Same file, opposite readings, which is the exact failure a second implementation exists to prevent. Both now decide the shape up front by identical rules, and a test asserts they agree on the verdict and the full finding set across 26 malformed shapes.
  • server_head is checked. The bundle carries the hash of the chain's last record and neither verifier ever looked at it, so an export could claim any head at all, including one from a different stream, and still verify.
  • An account could grant itself the top tier. PUT /v1/account/plan took the plan from the request body behind an owner-only permission, so a free account could name itself enterprise and receive unlimited events, seats, SSO and exports. An upgrade now requires the payment provider's secret; a downgrade stays self-service.
  • A tab defeated every guardrail. Arguments are matched as JSON text, where a real tab becomes the two characters backslash-t, so rm and -rf separated by a tab matched nothing. Argv arrays had the same problem through the decide() API. Both are normalized before matching now.
  • rm -f one-file.txt is no longer refused outright. It was denied by a pack that is on by default, and a guardrail that blocks ordinary work gets switched off within a day, taking the working rules with it. Recursion is what cannot be undone, so recursion is what is refused; a forced non-recursive delete asks for a recorded human decision instead.
  • Rotating an agent key with the wrong old key changed nothing, and said it succeeded. The old key stayed active and a second live key appeared. It is a 404 now, with nothing written.
  • Cached-read prices for o1 and o3-mini were half the real figure, so spend caps under-counted every cached call on those models.
  • The CLI stopped printing tracebacks. A missing sink, a directory where a file was expected, an unreadable file and a mistyped rule pack all say what happened and what to do. A mistyped pack used to print the whole catalogue and exit 0, which looked exactly like success.
0.2.17August 4, 2026Guardrails
  • Everything we advertise is now actually blocked. Testing a fresh install against our own marketing copy found five claims the code did not keep: chmod 777 lived in a pack the default install never armed; TRUNCATE orders slipped through because the rule required the optional TABLE keyword; dd of=/dev/ and kubectl delete namespace had no rule at all; and the token pattern matched only the retired sk- key format, missing every current sk-proj- and sk-ant- key.
  • The access pack is armed by default, so world-writable chmod and disabling MFA are blocked out of the box. Existing projects keep the packs written in their .provenrail.json; an upgrade never starts blocking on its own.
  • Production rules that fire under a coding agent. The pack matched only tool names like deploy*, which Claude Code never emits, so it was inert for the host we ship for. A connection string pointed at production and a deploy command now ask for a human, rather than being silently allowed.
  • The copy is a test now. Every capability named on the site, in both READMEs and in the PyPI summary is asserted command by command against the default install, alongside 17 ordinary commands that must not trip. Marketing and code can no longer drift apart quietly.
0.2.16August 4, 2026Guardrails
  • The policy is found from a subdirectory. pr guard install writes the policy at the repo root, but agents are routinely launched from a package inside a monorepo. The lookup only checked the current directory, so a session started in apps/web found no policy and allowed everything, silently. It now searches upward to the repo root. This was the worst failure available: you installed it, so you believed you were covered.
  • Silence is no longer a valid state. If the hooks are wired but no rules are armed, the hook now says so, once a day rather than on every call. A silent allow is indistinguishable from a working guardrail.
  • The journal stays with the policy. It is anchored to the directory holding .provenrail.json, so a session started in a subdirectory no longer opens a second, invisible journal with its blast-radius counters reset to zero.
  • The plugin shim forwards those warnings instead of discarding them, which had been hiding exactly the message a user needs.
0.2.15August 4, 2026Guardrails
  • Blast-radius caps now actually cap. Every hook invocation is a separate process, so a limit rule counting in memory reset on every call and capped nothing, while pr guard status still reported it as armed. A cap that never fires is worse than no cap. Counts are now carried across hook processes, per session, and pruned after seven days.
  • Stated honestly. The counter file is local and editable, so it is a convenience and not evidence. deny and require_oversight never read it, which means editing or deleting it cannot unblock anything. pr guard reset clears it.
0.2.14August 4, 2026Distribution
  • Installable as a Claude Code plugin. /plugin marketplace add pofky/provenrail then /plugin install provenrail-guard@provenrail. No settings file to edit. The hook shim fails open: if Provenrail is not installed it exits silently rather than blocking every tool call, and warns once a day instead. A guardrail that bricks your agent gets uninstalled before it guards anything.
  • A guide for the thing people actually search for. Claude Code guardrails covers why the permission prompt is not a control, what each rule pack blocks, and why some rules ask instead of deny.
  • Package metadata. Keywords, classifiers and project links on PyPI, and a README that leads with the guardrail rather than the threat model.
0.2.13August 4, 2026Guardrails
  • Guard a coding agent in one command. pr guard install arms the destructive, secrets and production rule packs and wires them into Claude Code's own tool hooks. No SDK, no code change. rm -rf, terraform destroy, git push --force, DROP TABLE, chmod 777 and leaked API keys are blocked before they run, and the agent is told which rule fired.
  • A human decision stays a human decision. A rule that requires oversight becomes a permission prompt rather than a hard block, and your approval is recorded as human oversight in the signed chain. Flattening that into a block is how guardrails get uninstalled on day one.
  • The verdict never depends on the network. It is computed offline before anything is sent, so an unreachable sink can never turn a deny into an allow. A decision that cannot be recorded is journalled locally and reported as unsigned and pending, never as proof.
  • Receipts. pr guard status shows what is armed and what it blocked; pr guard receipt exports the proof so you can pr verify it yourself. pr risk now counts escalations separately from denials.

Honest scope: this covers tool calls the host routes through its hooks. It cannot constrain a process that never calls them.

0.2.10 to 0.2.12July 30, 2026Guardrails
  • A catalogue of prebuilt guardrails. Seven packs and 31 rules (35 today) covering destructive actions, credentials, money movement, production infrastructure, access changes, data exfiltration and blast-radius caps. Enable by name in .provenrail.json. Nothing is on by default: an upgrade must never start blocking your agent on its own.
  • Rules you can check instead of hope about. pr rules lists the catalogue with each rule's false-positive risk; pr rules --check bundle.json reports which rules would match the tool names in a real recorded run, and says plainly that content rules cannot be judged from names alone.
  • Denials as evidence. A blocked action is written into the signed chain, shown in red on the public proof page, and can fire a signed webhook the moment it is ingested.
  • Re-running an agent works. Multiple runs on one stream are now verified as independent sessions, each rooted in its own genesis record, in both the Python and browser verifiers. A persistent device key at .provenrail.key keeps runs on a pinned stream signing under one identity.
0.2.7 to 0.2.9July 30, 2026Integrations
  • Agno, Hermes and the Claude Agent SDK. Capture through each framework's own hook mechanism, with no core changes on their side. A policy denial is recorded as a denial, never folded into "tool failure", because the two are different facts.
  • LangChain compliance handler. A ComplianceCallbackHandler that signs and hash-chains every model and tool call off-box.
0.2.2 to 0.2.6June 12, 2026Platform
  • Bitcoin anchoring. OpenTimestamps proofs verified as a step in both verifiers, held in agreement by frozen conformance vectors.
  • A second implementation, in your browser. verify.js is an independent verifier (WebCrypto Ed25519, JCS canonicalization, RFC 6962 Merkle proofs) that runs client-side, so the hosted verifier trusts not even our server.
  • TypeScript recording SDK. A run recorded in TypeScript is byte-for-byte compatible with one recorded in Python, proven by a cross-language test rather than asserted.
  • Transparency log and witnesses. Per-account RFC 6962 log with inclusion and consistency proofs and independent witness cosignatures, so a sink cannot show two different histories.
  • Selective disclosure, evidence packs, replay and diff. Redact a field without breaking the chain; pr pack builds a self-contained auditor ZIP; pr diff compares two integrity-checked runs so a difference is a real behavioural change.
0.2.1June 11, 2026CLI
  • Verify your own run, free and local. New pr export pulls a run you recorded out of the local sink into a bundle, so you can close the full loop on your own machine: record, pr export, pr verify, with no account.
  • quickstart keeps a read token. pr quickstart now saves a read token in .provenrail.json, which is what makes pr export work with zero extra setup.
  • Deterministic tests. The test suite no longer reads the developer's installed license, so free-tier behavior is verified consistently on every machine.
0.2.0June 11, 2026CLI
  • Commercial licensing. pr activate verifies a signed license key fully offline and runs the self-hosted deployment at the licensed tier. Plan limits and feature gates are enforced server-side; the integrity guarantee never depends on any of it.
  • Install that survives a system Python upgrade. Recommended install moved to uv tool install provenrail, which brings its own pinned Python.
0.1.xJune 2026Launch
  • The core. Off-box, hash-chained, signed records with an append-only sink and an independent server receipt chain.
  • Two SDKs in lockstep. Python and TypeScript recording SDKs producing byte-for-byte compatible records, with drop-in capture for OpenAI, Anthropic, LangChain, and MCP.
  • An offline verifier. pr verify and an in-browser verifier that trust nobody, backed by a frozen public conformance suite both must agree on.
  • Trusted time and transparency. RFC 3161 timestamps, a witnessed transparency log, SCITT COSE receipts, verifiable redaction, and OpenTimestamps (Bitcoin) proof verification.
  • Evidence packs. One-command evidence packs mapping recorded events to EU AI Act Article 12 and HIPAA audit-control requirements.
