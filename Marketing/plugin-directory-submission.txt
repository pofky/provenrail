=== PLUGIN NAME ===

provenrail-guard


=== DESCRIPTION ===

Counts your agent's subagent spawns and asks before the twenty-first, because nothing else limits how wide a session fans out. Plus a day spend cap and delete rules that screen where a command points rather than what it is called. Deterministic, offline, and it runs in `claude -p` and CI where the auto mode classifier does not.

=== CATEGORY ===

security


=== IF THERE IS A LONGER "WHAT IT DOES" FIELD ===

Claude Code refuses a subagent at depth 3 of 3. That bounds how deep the tree goes. Nothing anywhere bounds how wide it goes, and width is what the reports are about: issue #68619 is open and records 1.2 million tokens consumed in roughly 30 minutes with CLAUDE_CODE_FORK_SUBAGENT=0 ignored, and #68110 records general-purpose subagents recursively spawning unbounded children. Every subagent starts a fresh context that is billed and metered on top of the one it came from.

This counts the spawns and asks you before the twenty-first. The cap of 20 comes from a measured distribution rather than from a round number: over 915 real sessions, 12 percent spawn a subagent at all, and among those the median is 4 and the 90th percentile is 35, so a low cap would interrupt ordinary work. At 20 the rule reaches 1.6 percent of all sessions and still catches every runaway in that corpus, the widest of which spawned 93 times and spent 253 dollars on subagents alone. It asks rather than blocks, because wide fan-out is often exactly what you wanted, and where there is no permission prompt to answer, unattended or in CI, the question becomes a refusal.

45 more rules are armed by default across eight packs, screening where a delete or a git command actually points rather than what it is called, so rm -rf ./build runs silently and rm -rf ~ is refused. The git rules read the repository first and stay quiet when the tree is clean and pushed.

Auto mode already covers a lot of the destructive-command case for interactive sessions on a paid plan, and it is good. Two things it does not do: there is no dollar cap on an interactive session, and it is simply absent from claude -p, the Agent SDK, Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and Claude Platform on AWS, which all start in Manual. Hooks fire in all of those, including inside subagents, which was verified rather than assumed.

Nothing is installed and nothing leaves the machine. No account, no pip install, no server, no network call. pr report --fanout reads transcripts you already have and tells you how wide your own sessions spread, offline.

If anything at all goes wrong the tool call proceeds: the hook exits with no opinion rather than failing. A guardrail that bricks your agent is worse than no guardrail.

=== IF THERE IS AN "INSTALL" OR "USAGE" FIELD ===

/plugin marketplace add pofky/provenrail
/plugin install provenrail-guard@provenrail
/guard-budget 25

/guard-status shows what is armed and what it has actually stopped. /guard-rules prints every rule including the packs that are off by default. /guard-card produces a paste-safe summary with every operand stripped.
