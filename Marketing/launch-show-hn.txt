Show HN: I read 2,154 of my own Claude Code transcripts. $7,856 in 31 days

I have been running coding agents hard for a month and had no idea what they were actually doing, so I wrote a tool that reads the transcripts that are already sitting in ~/.claude/projects and tells you.

One command, no setup, no account, no network. It found 942 sessions across 23 projects, 79,782 tool calls, 51,443 shell commands, 7,009 distinct files written or edited, and an estimated $7,856.31 of model spend. Then it replays every command I ran back through a policy engine and tells me which ones would have been stopped: 29 refused outright and 483 that should have come to me first. Top offenders were deploy commands, recursive deletes pointed outside the project, and reads of .env files.

The number I care about most is the one it is honest about. The cost is an estimate at API list price and it is a floor, measured about 12 per cent below Claude Code's own recorded total across the 49 sessions where both figures exist. Two causes I can name and cannot detect from a transcript: fast mode bills Opus 5 at $10/$50 per million tokens against the standard $5/$25, and web search is $10 per 1,000 searches. I did not invent a multiplier to close the gap, so the two numbers are printed side by side and you can see the disagreement.

There is a `--share` mode that strips the root path and hashes project names, and every command is reduced to its verb and flags with all operands dropped, so the output is safe to post. A test asserts no path, hostname, URL or key survives that reduction, over two corpora.

The same engine also enforces a spend cap. `pr guard budget 25` and the tool hook refuses the next tool call once the day's estimated spend crosses it, which is a turn late by construction so it never claims to stop you at an exact dollar.

Four objections I expect, answered up front. First, Claude Code already blocks destructive commands: yes, and it does it well. Auto mode is the built-in starting mode on Pro, Max and Team, it runs git status before a command that would discard uncommitted work, and it refuses a critical-path rm even when a hook says allow. If interactive work is all you run, you already have most of that for free. What it does not do is stop spending, leave an artefact you can show anyone, or run at all in `claude -p`, the Agent SDK, Bedrock, Google Cloud's Agent Platform or Microsoft Foundry, which all start in Manual on every plan. Second, a hook is the wrong layer and you should containerise: correct, for a hostile agent. This is for a trusted agent that makes mistakes, and it is honest about that on the page. Third, you can defeat a pattern: yes, `V=-rf; rm $V`, a delete inside a python -c, a script invoked by name. Target resolution buys precision on what agents actually emit, not immunity to someone working around it. Fourth, false positives: that is why the rules screen where a command points rather than what it says. Over 36,977 real commands, verb matching interrupted 923 and target resolution interrupts 222, and on 40 commands taken from public Claude Code data-loss issues verb matching caught none of them.
